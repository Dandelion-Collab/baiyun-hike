# 夜间可通行性规则（checker / router 共用）

本文件是**判定口径**。代码里的阈值必须与本文一致；改口径先改这里。

## 1. 时间窗格式

- `HH:MM-HH:MM`，24 小时制
- 多个窗口用英文分号分隔：`06:00-12:00;14:00-18:00`
- 全天开放写 `00:00-24:00`
- **区间为半开区间 `[start, end)`**：`06:00-22:00` 表示 22:00 整点起不可用

> 为什么半开：宁严勿松。差一分钟被拒，用户可以接受；放进去后被关在里面，不能接受。

## 2. 节点判定（能不能进）

用户在时刻 `t` 到达节点 N，若 `t` 落在 N 的任一 `open_windows` 内 → 可进；否则 → 不可进。

## 3. 边判定（能不能走）

从节点 A 于时刻 `t1` 出发、`t2` 到达 B，必须**整段落在**边的 `passable_windows` 内：

```
存在窗口 [s, e) 使得 s <= t1 且 t2 < e
```

只有出发时刻在窗口内是不够的——出发时没关，走到一半关门，同样不允许。

## 4. night_access 字段含义（POI 表）

| 取值 | 含义 | 用法 |
|---|---|---|
| `open` | 夜间开放 | 可安排夜间活动 |
| `gate_only_out` | 夜间只出不进 | 不可作为夜间起点；可作为终点 |
| `closed` | 夜间关闭 | 夜间不得安排 |
| `na` | 不适用（无门禁/室内场馆） | 按 open_windows 判断即可 |

## 5. 判定优先级

1. 先判 `closed_weekday`（闭馆日）→ 命中则直接 `error`，不再判其他
2. 再判 `open_windows` 是否覆盖"到达时刻 ~ 离开时刻"
3. 再判 `night_access`（`gate_only_out` 不能作为起点）
4. 最后判照明与坡度（只出 `warn`，不阻断）

## 6. 无法通行时的输出规范（重要）

**不许硬给一条路。** 必须输出三段：

1. **最远可达点**：在约束下实际能到哪儿
2. **原因**：哪条边/哪个门、什么时刻关闭（带依据）
3. **建议**：改时间 / 改入口 / 改目标，三选一以上

示例：

> 22:00 从南门出发无法登顶。南门 21:30 后只出不进；最近可行入口为西门（至 22:30），
> 但西门→明珠楼路段 22:00 后不能再走。建议：明早 6:00 后从南门上山，
> 或今晚从西门步行至明珠楼后原路返回。

## 7. 数据可信度

- 每行带 `verified_at`（如 `2026-11`）
- `note` 含"待校验"的行：坐标或时间未核实，**不得单独作为推荐依据**，输出时标注 `unverified=true`
- 对外展示必须带免责：数据为人工整理，以景区公告为准

## 8. 边界用例（写测试必须覆盖）

| 场景 | 期望 |
|---|---|
| 21:30:00 走 `06:00-21:30` 的边 | 不可走 |
| 21:29 出发、21:45 到达 `06:00-21:30` 的边 | 不可走（整段覆盖失败） |
| 22:00 从南门进 | 不可进（门 21:30 关） |
| 23:30 任意门 | 无法登顶，输出拒答 |
| 19:00 南门出发 | 可到摩星岭 |
| 21:00 南门出发 | 可到山顶广场，摩星岭不可达 |
